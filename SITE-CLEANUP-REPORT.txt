AUTOMATIC VS MANUAL
- Homepage portrait preview: automatically selects newest biographies (based on stored ranking); manual people list overrides the first slots. Number of portraits and tint are manually adjustable in Homepage Design.
- Homepage press/exhibition features: automatic according to their settings and the relevant Press & Media / Exhibitions collections. Press entries can pin an article and upload their own logo or screenshot.
- Site layout and typography: controlled by settings files; content editors do not necessarily change layout.

ISSUES OBSERVED / NOT AUTOMATICALLY REWRITTEN
- assets/site.css has accumulated many historical override rules and !important declarations. This is real maintenance debt. Bulk removal without a browser-based visual regression check could break mobile banners, biographies, QR page and other previously fixed layouts, so it was intentionally left in place.
- Legacy content/settings/site.yml is still loaded first as a fallback, with individual settings files overriding matching keys. Deleting it without a complete key audit could change fallback defaults.
- Many old INSTALL and README variants exist at repository root. They were not deleted because this update package only changes live site files. Archive older instructions after checking they are no longer needed.
- Pages CMS may not offer collapsible section headings in the current flat object editor. Numbered label prefixes are the safe organizational approach without changing the underlying data format.
- Some design values in CSS still use older fixed pinks for decorative gradients. This update does not replace all of those because some may be intentional paint effects. Main project pink remains #E85395.
- Live browser appearance and Pages CMS save interaction were not tested; only static generation and YAML validation were checked.

INSTALLATION
Replace exactly these four repository files:
  .pages.yml  (hidden file, show hidden files in Finder with Command+Shift+.)
  assets/site.css
  scripts/build.py
  content/settings/homepage.yml
Wait for the GitHub/Cloudflare deployment, then refresh the homepage and Pages CMS.
